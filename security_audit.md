# Security Code Review

**Scope:** Go/Gin API security review for SQL injection, mass assignment, authentication/RBAC, and sensitive-data exposure. The findings below record the review and triage; `False Positive` means the suspected vulnerability is not present in the examined path.

## Findings and triage

| # | Severity | Finding | Evidence | Triage |
|---|---|---|---|---|
| 1 | Medium | A role change does not invalidate already-issued JWTs. Middleware authorizes from the role claim, so a demoted account can retain its previous privileges until the token expires. The default TTL is 24 hours, but configuration only enforces a positive duration, not a 24-hour maximum. | [`internal/auth/jwt.go:43-56`](./internal/auth/jwt.go#L43), [`internal/middleware/auth.go:30-37`](./internal/middleware/auth.go#L30), [`internal/config/config.go:78-83`](./internal/config/config.go#L78) | **Tracked for Later** — document and enforce a maximum TTL, or add revocation/current-role checks if immediate demotion is required. |
| 2 | Low | Exported alternate router constructors wire protected groups without authentication/RBAC. They are unsafe if selected for a production server, although the current executable uses the secure dependency constructor. | [`internal/app/app.go:32-45`](./internal/app/app.go#L32), [`internal/app/app.go:47-49`](./internal/app/app.go#L47), [`internal/app/app.go:87-94`](./internal/app/app.go#L87), [`cmd/api/main.go:80-92`](./cmd/api/main.go#L80) | **Tracked for Later** — make insecure constructors clearly test-only or otherwise reduce the chance of production misuse. |
| 3 | Low | Suspected SQL injection through movie filters is not present in the reviewed GORM queries: request values are bound through placeholders, and the SQL fragments and ordering expressions are static. | [`internal/repository/movie_gorm.go:182-186`](./internal/repository/movie_gorm.go#L182), [`internal/repository/movie_gorm.go:203-214`](./internal/repository/movie_gorm.go#L203) | **False Positive** — retain parameterized queries and static SQL identifiers. |
| 4 | Low | Suspected SQL injection through user email and role filters is not present in the reviewed GORM queries: values are passed as bound parameters. | [`internal/repository/user_gorm.go:57-62`](./internal/repository/user_gorm.go#L57), [`internal/repository/user_gorm.go:75-80`](./internal/repository/user_gorm.go#L75) | **False Positive** — retain parameterized queries. |
| 5 | Low | Suspected mass assignment into the persistence user model is not present in registration or role-update paths. Requests use dedicated DTOs; registration assigns the viewer role server-side, and role updates go through service validation. | [`internal/model/user.go:32-45`](./internal/model/user.go#L32), [`internal/service/auth_service.go:58-64`](./internal/service/auth_service.go#L58), [`internal/handler/user_handler.go:97-118`](./internal/handler/user_handler.go#L97) | **False Positive** — preserve request DTOs and server-side role assignment. |

| 7 | Low | Suspected missing authentication/RBAC on the running API is not present in the executable's router setup: it constructs the router with `NewRouterWithDeps`, which enables secure routing, and protected groups run authentication before role checks. | [`cmd/api/main.go:80-92`](./cmd/api/main.go#L80), [`internal/app/app.go:47-49`](./internal/app/app.go#L47), [`internal/app/app.go:87-94`](./internal/app/app.go#L87) | **False Positive** — production routing is protected; see Finding 2 for the separate alternate-constructor footgun. |

## Summary

The inspected SQL, request-binding, production route, and response-serialization paths use the expected controls. The actionable residual items are JWT role staleness until expiry and the insecure alternate router constructors. No application code was modified for this review; this report is the deliverable.
