# Security Code Review

**Scope:** Go/Gin API security review for SQL injection, mass assignment, authentication/RBAC, and sensitive-data exposure. The findings below record the review and triage; `False Positive` means the suspected vulnerability is not present in the examined path.

## Findings and triage

| # | Severity | Finding | Evidence | Triage |
|---|---|---|---|---|
| 1 | Medium | A role change does not invalidate already-issued JWTs. Middleware authorizes from the role claim, so a demoted account can retain its previous privileges until the token expires. The default TTL is 24 hours, but configuration only enforces a positive duration, not a 24-hour maximum. | [`internal/auth/jwt.go:43-56`](../internal/auth/jwt.go#L43), [`internal/middleware/auth.go:30-37`](../internal/middleware/auth.go#L30), [`internal/config/config.go:78-83`](../internal/config/config.go#L78) | **Tracked for Later** — document and enforce a maximum TTL, or add revocation/current-role checks if immediate demotion is required. |
| 2 | Low | Exported alternate router constructors wire protected groups without authentication/RBAC. They are unsafe if selected for a production server, although the current executable uses the secure dependency constructor. | [`internal/app/app.go:32-45`](../internal/app/app.go#L32), [`internal/app/app.go:47-49`](../internal/app/app.go#L47), [`internal/app/app.go:87-94`](../internal/app/app.go#L87), [`cmd/api/main.go:80-92`](../cmd/api/main.go#L80) | **Tracked for Later** — make insecure constructors clearly test-only or otherwise reduce the chance of production misuse. |
| 3 | Low | Suspected SQL injection through movie filters is not present in the reviewed GORM queries: request values are bound through placeholders, and the SQL fragments and ordering expressions are static. | [`internal/repository/movie_gorm.go:182-186`](../internal/repository/movie_gorm.go#L182), [`internal/repository/movie_gorm.go:203-214`](../internal/repository/movie_gorm.go#L203) | **False Positive** — retain parameterized queries and static SQL identifiers. |
| 4 | Low | Suspected SQL injection through user email and role filters is not present in the reviewed GORM queries: values are passed as bound parameters. | [`internal/repository/user_gorm.go:57-62`](../internal/repository/user_gorm.go#L57), [`internal/repository/user_gorm.go:75-80`](../internal/repository/user_gorm.go#L75) | **False Positive** — retain parameterized queries. |
| 5 | Low | Suspected mass assignment into the persistence user model is not present in registration or role-update paths. Requests use dedicated DTOs; registration assigns the viewer role server-side, and role updates go through service validation. | [`internal/model/user.go:32-45`](../internal/model/user.go#L32), [`internal/service/auth_service.go:58-64`](../internal/service/auth_service.go#L58), [`internal/handler/user_handler.go:97-118`](../internal/handler/user_handler.go#L97) | **False Positive** — preserve request DTOs and server-side role assignment. |
| 6 | Low | Suspected password-hash exposure in JSON responses is not present in the reviewed user paths. The persistence field is excluded from JSON, and handlers return `UserResponse` values built without the hash. | [`internal/model/user.go:20-27`](../internal/model/user.go#L20), [`internal/model/user.go:47-68`](../internal/model/user.go#L47), [`internal/handler/user_handler.go:45-51`](../internal/handler/user_handler.go#L45), [`internal/handler/user_handler.go:77-78`](../internal/handler/user_handler.go#L77), [`internal/handler/user_handler.go:116-118`](../internal/handler/user_handler.go#L116) | **False Positive** — continue returning response DTOs rather than persistence models. |
| 7 | Low | Suspected missing authentication/RBAC on the running API is not present in the executable's router setup: it constructs the router with `NewRouterWithDeps`, which enables secure routing, and protected groups run authentication before role checks. | [`cmd/api/main.go:80-92`](../cmd/api/main.go#L80), [`internal/app/app.go:47-49`](../internal/app/app.go#L47), [`internal/app/app.go:87-94`](../internal/app/app.go#L87) | **False Positive** — production routing is protected; see Finding 2 for the separate alternate-constructor footgun. |
| 8 | Low | Duplicate registration returns `422 validation_error` with an "email already registered" message, so callers can determine whether an email has an account even though login failures are generic. | [`internal/handler/auth_handler.go:48-58`](../internal/handler/auth_handler.go#L48), [`internal/service/auth_service.go:60-68`](../internal/service/auth_service.go#L60) | **Tracked for Later** — if registration privacy is required, return the same accepted response for new and duplicate email addresses. |
| 9 | Medium | Browser authentication uses an HttpOnly JWT cookie, so browser requests need CSRF defenses. The web middleware requires a double-submit token and checks a supplied Origin against the request host; SameSite=Lax is defense in depth. The JSON API continues to use only the Authorization header. | [`internal/handler/web/middleware.go`](../internal/handler/web/middleware.go), [`internal/handler/web/auth.go`](../internal/handler/web/auth.go) | **Fixed Now** — unsafe web requests are checked before handlers; browser JWTs are not accepted as API credentials. |
| 10 | Low | Cookie transport depends on deployment configuration. With `COOKIE_SECURE=false`, cookies can be sent over cleartext HTTP; leaving this value false behind HTTPS weakens session confidentiality. | [`internal/config/config.go`](../internal/config/config.go), [`internal/handler/web/auth.go`](../internal/handler/web/auth.go) | **Tracked for Later** — `COOKIE_SECURE` is documented and must be true in HTTPS deployments; ensure deployment configuration sets it. |
| 11 | Low | Suspected reflected/stored template injection through movie/user text is not present in the audited web templates. Data is rendered with `html/template` contextual escaping; the source audit found no `text/template`, trusted `template.HTML`/related conversions, inline event handlers, or inline script bodies. | [`internal/handler/web/audit_test.go`](../internal/handler/web/audit_test.go), [`web/templates`](../web/templates) | **False Positive** — retain contextual autoescaping and do not introduce trusted-type conversions. |
| 12 | Low | Suspected missing browser content policy is not present: web routes set a same-origin CSP, nosniff, and referrer policy. API routes do not receive web-only headers. | [`internal/app/app.go:164-170`](../internal/app/app.go#L164), [`internal/app/web_test.go`](../internal/app/web_test.go) | **False Positive** — web-only security headers are applied on the UI route group and covered by tests. |

## Summary

The inspected SQL, request-binding, production route, and response-serialization paths use the expected controls. The actionable residual items are JWT role staleness until expiry, the insecure alternate router constructors, and account enumeration through duplicate-registration responses. No application code was modified for this review; this report is the deliverable.
